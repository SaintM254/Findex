# Findex 1.1 — prepared update, signing blocked

Android versionName **1.1**, versionCode **2**, applicationId **app.findex.files**.

## Performance changes

- A file browser, not an index-loading screen: native startup returns a bounded navigation snapshot immediately. Files and folders are enumerated directly from the current directory, without waiting for a recursive scan.
- No complete-library JSON transfer on startup/resume. Native lists/search results use bounded pages (80 rows); sidebar/recent metadata is bounded to 76 entries.
- Folder calculations are cached and linear-time, replacing the repeated full-map construction that could lock up the UI on large libraries.
- Background indexing records lightweight filesystem metadata and releases the writer lock between small batches. PDF text/media probing is deferred to idle/charging work or an explicitly opened details view.
- The completed-index observer consumes every finished work ID, preventing repeat-refresh storms.
- The hamburger touch target is at least 44 pixels. Large mobile blur layers are removed, and navigation no longer causes expensive folder-tree recalculations.
- A live file observer refreshes the visible folder after filesystem changes. Ordinary browsing does not need Internet access or a provider key.

## Appearance

- Uses the owner's supplied blue SVG folder icon, including its paper shadow and Poppins Bold lettering converted to paths.
- Updates launcher densities, adaptive foreground/splash, favicon, in-app mark, light-blue surfaces, and matching dark-blue appearance.
- Applies the supplied screenshot: removes the top-right theme toggle/avatar and the main New folder/Add files row. The hamburger remains. Creation/import actions are icon-only tools inside navigation; theme choices remain under Settings. The unmarked welcome and storage sections are not removed.

## Signature continuity

The expected v1.0 certificate SHA-256 is pinned in `signing/release-policy.json`:

`cdc51b906b006af79a6983318f8bc448c74453732842ca68a7fdbd160f76a3af`

A new signing identity was generated for v1.1 with owner authorization because the v1.0 private key was unrecoverable. v1.0 therefore requires a one-time uninstall; v1.1+ shares one identity the restored workspace. The repository contains only a public backup-recipient certificate; the encrypted CI backup cannot be decrypted without its private recipient key. A public APK/certificate cannot recreate the private signing key.

**No new key is generated and no differently signed APK is published as an in-place update.** The old bootstrap is retired. `scripts/sign-compatible-release.sh` requires the original keystore, checks its certificate before signing, verifies the signed APK again, and checks the unchanged app ID/increased versionCode.

To publish an update that installs over v1.0, restore the original keystore (or the decryptable private backup) through a secure channel. Never put keys or passwords in chat. If it cannot be recovered, Android requires a one-time reinstall for a different signing identity; that cannot be hidden or bypassed.
